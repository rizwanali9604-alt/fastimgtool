About this compressor

This page shrinks one image at a time in the browser using the browser-image-compression library in a Web Worker. It is not a lossless archive tool. JPEG and WebP output throw away detail on purpose so the file gets smaller. PNG output is lossless and often grows a photograph.

The script aims for about half the original byte size (maxSizeMB ≈ 49% of the source) and also caps the longer side (default 2048px). If the source is already small or already compressed, the “Saved %” can be well under 50%. That is expected, not a broken download.

How to compress

  1. Drop a JPEG, PNG, WebP, GIF, or BMP. Decoding happens locally; the file is not posted to FastImageTool.
  2. Set quality (default 85%). Lower quality usually means a smaller JPEG/WebP.
  3. Pick output format. JPEG for Meesho/Amazon photos. WebP for modern sites. PNG only if you must keep transparency or sharp UI text.
  4. Optionally lower the max longer side if the photo is a 12MP phone shot destined for a 600px catalog card.
  5. Press Compress & download. The page shows before/after bytes, then starts a download named *-compressed.jpg|webp|png.

Frequently asked questions

Why didn’t the file get 50% smaller?

The worker stops when it cannot reduce further without wrecking the image, or when the source is already near the target. Screenshots and tiny logos barely shrink. Try JPEG or WebP, quality 75–85%, and a smaller max side.

Does PNG compression keep transparency?

PNG output can keep alpha. JPEG cannot; transparent pixels become opaque (typically white-ish after encode). The format hint on the JPEG option mentions this when the source is a PNG.

Is this the same as WhatsApp compression?

No. WhatsApp applies its own resize after you send. Compress here first if you need a file under an email or panel limit before the chat app touches it. See the WhatsApp guide.

Can I compress HEIC?

Not on this page. Convert with HEIC to JPG first, then compress the JPEG.
